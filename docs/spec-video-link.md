# Spec：群聊视频链接解析并发送原视频

状态：已实现（2026-10-23）。审核结论：自动解析；其他网站要做（尤其 B 站）；默认 10 分钟 / 50 MB；所有群。私聊里发链接也会解析。

> 2026-10-23 修订：改成 send_video 工具（她调用，视频放进发件箱跟回复一起发）。自动解析保留为开关 video.auto（默认开）：群里出现视频链接时让她跑一轮去调工具，花 credits，记在群上。去掉了网关直接发的信息行（sendInfo），由她自己评价。下载目录只做中转，文件 1 小时后删、总量上限 500 MB。下文第 3、4、6 节描述的是第一版（网关直接发送），以这段为准。

## 1. 目标

群友在群里发抖音、B 站或其他视频网站的分享链接时，机器人把视频下载下来，作为 QQ 视频消息发回群里，附一行"平台 · 标题 · 作者 · 时长"。她知道这条链接是什么视频，被叫到时可以接着聊。

不做：直播、番剧/付费内容、图文笔记（抖音图集、小红书图文）、音乐。

## 2. 调研结论

| 方案 | 结论 |
|---|---|
| [fllesser/nonebot-plugin-parser](https://github.com/fllesser/nonebot-plugin-parser)（MIT，229 星，2026-10 仍在更新） | 目前最全的 QQ 机器人链接解析插件：B 站、抖音、快手、微博、小红书、YouTube、TikTok、Twitter、AcFun、NGA。但它是 NoneBot2（Python）插件，依赖 nonebot 的日志、配置、本地存储，没法直接装进我们的 Koishi 网关；单独起一个 NoneBot 进程又要再接一遍 QQ，不划算。**借它的解析逻辑**：抖音用的是 `www.douyin.com/aweme/v1/web/aweme/detail/` 网页接口，不需要登录；其他平台它自己也是交给 yt-dlp 下载。 |
| [koishi-plugin-douyin](https://npmjs.com/package/koishi-plugin-douyin) | Koishi 插件，只支持抖音，周下载 19，基本没人维护，不用。 |
| nonebot-plugin-analysis-bilibili / bilichat | 只做 B 站，而且只发卡片不发视频，或者已进入维护模式。 |
| yt-dlp | 支持上千个视频网站，B 站、YouTube、微博、快手等都能直接下，是"任意链接"的唯一现实方案。**抖音要新鲜 cookie**，不登录基本下不了，所以抖音单独走上面那个网页接口。B 站高画质是音视频分离的，要 ffmpeg 合并。 |
| QQ 官方机器人发视频 | 我们用的适配器 `@satorijs/adapter-qq` 4.14 已经支持 `h.video(本地文件)`：小于 3 MB 直接 base64 上传，超过的自动走分片上传（upload_prepare）。**大小上限没找到官方原文**：第三方资料写视频 100 MB，有 SDK 里写的是 20 MB，要你线上实测一次确认。 |

结论：不整体搬别人的插件，在网关里写一个小的视频模块。抖音解析移植自 nonebot-plugin-parser（MIT，保留版权声明，跟表情包库移植 qq-bridge 一样处理）；B 站和其他网站交给 yt-dlp。

## 3. 行为

1. 群里任何一条消息（需要已开通"接收所有消息"；没开通时只有 @ 她的消息才收得到）里含有支持的链接，网关就处理，不经过模型、不花 token。
2. 先发一行信息：`【B站】标题 · UP主 · 3:12`（可在配置里关掉）。
3. 下载完成后用这条群消息的被动回复额度发出视频。下载失败、超过时长或大小上限时，只发信息那一行，后面跟一句原因（比如"视频太长了，不搬了"），不刷屏报错。
4. 同一个群里同一个视频 N 分钟内（默认 30）只处理一次，避免多人转发同一个链接时重复发。
5. 这条消息进入她上下文的时候，链接后面附上 `[视频：B站《标题》 UP主，网关已经把视频发到群里了]`。她被叫到时知道大家在说哪个视频，但**不能看视频内容**（只知道标题、作者、简介）。
6. 她自己不会因为有链接就主动开口，触发规则照旧（@、叫名字、插话概率）。

### 支持的链接

| 平台 | 识别 | 解析 / 下载 |
|---|---|---|
| 抖音 | `v.douyin.com/xxx` 短链、`douyin.com/video/<id>`、`iesdouyin.com/share/video/<id>`、`jingxuan.douyin.com` | 短链先跟随跳转拿到 id，再调网页详情接口，拿无水印播放地址直接下载 mp4 |
| B 站 | `b23.tv/xxx` 短链、`bilibili.com/video/BV…`（带 `?p=` 分 P）、`av…` | yt-dlp；没配 cookie 时 480P，配了 `BILIBILI_SESSDATA` 能到 1080P |
| 其他（可选） | 配置里列出的域名，默认：快手、微博视频、AcFun、YouTube、X/Twitter | yt-dlp 先只取信息（不下载）检查时长，再下载 |

"任意链接"不做成真的任意：群里发的普通网页链接（文章、商品）如果每条都丢给 yt-dlp 试一下，会白跑很多请求。改成域名白名单，看板上可以加。

QQ 小程序分享卡片（B 站、抖音的"分享到 QQ"有时发的是卡片不是链接）：官方机器人能不能收到卡片内容不确定，先写成"收到 ark/json 元素时从里面找链接"，你线上测一次。

## 4. 限制与保护

| 项 | 默认 | 说明 |
|---|---|---|
| 最长时长 | 10 分钟 | 超过只发信息行 |
| 最大文件 | 50 MB | 下载前按 Content-Length / yt-dlp 的预估大小检查；画质按大小上限自动选（同 nonebot-plugin-parser 的做法：`bv[filesize<=…]+ba/b[filesize<=…]`） |
| 并发 | 同时 1 个下载，其余排队 | 不拖慢聊天 |
| 下载超时 | 3 分钟 | 群聊被动回复窗口是 5 分钟，留出上传时间 |
| 缓存 | `data/cache/video/`，总量超过 1 GB 删最旧的 | 同一个视频再被发出时直接用缓存 |
| 群范围 | 全部群（可选只开某些群） | 看板多选 |

费用：不调用模型，不花 credits，不记账。看板总览加一个"今日解析视频 N 个"计数，日志里记每次的平台、标题、大小、耗时。

## 5. 配置（看板「配置」页，新分组「视频解析」）

```yaml
video:
  enabled: true
  groups: []            # 空 = 所有群
  platforms: [douyin, bilibili, other]
  otherSites: [kuaishou.com, weibo.com, acfun.cn, youtube.com, youtu.be, x.com, twitter.com]
  maxDurationMin: 10
  maxSizeMB: 50
  sendInfo: true        # 先发"平台 · 标题 · 作者 · 时长"那一行
  dedupeMin: 30
```

`.env`：`BILIBILI_SESSDATA=`（可选，B 站高画质）、`DOUYIN_COOKIE=`（可选，接口被风控时用）。

全部"实时"生效，不用重启。

## 6. 实现

```
gateway/src/video/
  detect.ts      从消息文本和卡片元素里找链接，按平台归类；短链在这里展开
  douyin.ts      抖音解析（移植自 nonebot-plugin-parser，保留 MIT 版权声明）
  ytdlp.ts       调 yt-dlp：--dump-json 取信息、按大小选画质下载、ffmpeg 合并
  index.ts       队列、去重、缓存、限制检查、发信息行和视频
```

- 挂在桥接的中间件里，放在触发判断之前，**和她的回复并行**：视频在后台下载，不阻塞她回话。
- 被动回复额度：现在每条消息最多回 4 次，视频 + 信息行占 2 次。如果她这一轮也要回（被 @ 了），她的回复优先，视频用剩下的额度；额度不够时视频改为主动消息发（每群每天 1000 条，够用）。
- 依赖：
  - yt-dlp：`pip install yt-dlp`（README 的"安装依赖"里加一行，和 pillow 一起）。
  - ffmpeg：用 npm 包 `ffmpeg-static`（自带二进制，不用让用户自己装）。
  - 启动时检查两者，没有就在日志里提示，只关掉 B 站和其他平台，抖音照常。
- 子进程照例 `windowsHide`（已有的 hide-windows 补丁会处理）。
- README「功能」表加一行，「致谢」加 nonebot-plugin-parser。

## 7. 风险

- **抖音接口随时可能被风控**（要签名参数 a_bogus 或 cookie）。nonebot-plugin-parser 现在还能用，但哪天失效我们要跟着它改；兜底是 `DOUYIN_COOKIE` + yt-dlp。
- **QQ 视频大小上限不确定**，第一次线上测试用一个 30 MB 左右的视频确认；如果上限是 20 MB，就把默认 maxSizeMB 调成 20。
- QQ 的视频消息要等腾讯那边转码，发出去后可能要几秒才能播放。
- 版权：只是把群友已经分享的链接转成视频，不主动搜索、不批量搬运。

## 8. 待你决定

1. **自动解析还是她来决定？** 推荐自动（网关直接发，不花 token，和其他机器人一样）。另一种是给她一个 `send_video` 工具，她觉得值得才发，或者群友让她"把这个视频发一下"才发，要花 token，而且她可能不发。也可以两个都做：自动解析默认开，工具留给"发一下上次那个视频"这种情况。
2. **其他网站要不要做？** 要做就得装 yt-dlp。B 站本来也要用它，所以装 yt-dlp 的成本已经付了，加其他网站基本是白送的。
3. **默认上限**：10 分钟 / 50 MB 可以吗？
4. **要不要做成仅限某些群**，还是默认所有群？

## 9. 测试

按约定不在本地跑：只做 `npm run check`（类型、编译、工具 schema）和 yt-dlp / ffmpeg 是否装上的检查，然后重启，你在群里发抖音、B 站链接各测一次，再用一个大视频测大小上限。
