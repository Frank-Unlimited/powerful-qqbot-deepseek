# Spec：翻唱工具

状态：已实现，待线上测试（2026-10-24）。第 11 节的问题都按推荐定了：允许环境自检、默认 60 秒、每天 10 首、仅限主人、不计费。

## 1. 目标

群友让机器人唱歌时，她调用 `sing_cover` 工具：网关在本机自动找到这首歌，去掉原唱人声，换成角色的嗓音（RVC 音色模型），再和伴奏混回去，作为 QQ 语音跟她这条回复一起发出。

不做：自己作词作曲、整首长歌（默认只唱一段）、实时变声、私聊以外的文件发送。

## 2. 调研结论

| 方面 | 结论 |
|---|---|
| 别人怎么接 QQ 群 agent | 没找到现成可用的 QQ 机器人翻唱插件。能找到的都是 RVC 翻唱网页工具（[RVC v2 AI Cover WebUI](https://huggingface.co/spaces/oItsMineZ/RVC-v2-AI-Cover-WebUI/tree/main/src)、[CoverGen](https://huggingface.co/spaces/nevreal/CoverGen-RVC/tree/main)、[AI-RVC](https://huggingface.co/spaces/mason369/AI-RVC/blob/main/README.md)、[Ultimate RVC](https://pypi.org/project/ultimate-rvc/)），流程都是：找歌 → 分离人声 / 伴奏 → RVC 换音色 → 混音。大模型（DeepSeek 也一样）只负责听懂要唱什么、调用工具，翻唱本身全在本地跑。 |
| 音色模型 | 任意 RVC v2 模型（`.pth`，最好带 `.index`），放在角色包的 `cover.modelDir`，不进 git。Hugging Face 上有很多免费模型（例如 [sxndypz/rvc-v2-models](https://huggingface.co/sxndypz/rvc-v2-models)）；**用唱歌素材训练的模型**唱歌比说话模型稳，RMVPE 提取音高的更好。注意模型许可证和声音版权。 |
| 开发机算力 | RTX 5060 笔记本版 8 GB 显存，但平时已被其他程序占用约 3.8 GB，**实际可用约 4 GB**。50 系显卡要 CUDA 12.8 版 PyTorch，RVC 官方安装脚本里锁定的旧版本跑不了（[RVC 50 系安装说明](https://github.com/RVC-Project/Retrieval-based-Voice-Conversion-WebUI/issues/2745)）。 |
| 歌源 | B 站搜索（项目里已有 yt-dlp，`bilisearch` 直接能搜），全曲免费。网易云 VIP 歌只能拿到 30 秒试听，不用。 |
| 发送 | 复用现有 `speak` 工具的路径：工具把音频文件放进发件箱，网关转成 silk 语音跟回复一起发。QQ 语音压缩很重，音乐音质会打折扣；语音时长上限没找到官方说法，默认唱 60 秒，线上实测确认。 |

## 3. 行为

1. 群友说「唱一首晴天」，她调用 `sing_cover(song="晴天 周杰伦")`。
2. 网关在 B 站搜歌，按规则挑原唱版（见第 5 节），下载音频。也可以直接给 B 站链接或 BV 号。
3. 分离出人声和伴奏，找到要唱的那一段（默认副歌：人声最集中的 60 秒），把人声换成角色音色，再和伴奏混音、淡入淡出、统一响度。
4. 工具返回「唱的是《晴天》- 周杰伦，副歌 1:12–2:12」，她顺口说一句，语音跟着这条回复发出。
5. 整个过程要在 QQ 被动回复的 5 分钟窗口内完成，工具超时设 270 秒。预计一首 4 分钟的歌 1–2 分钟能出来（估算，没实测）；同一首歌第二次唱直接用缓存的分离结果，更快。

失败时（找不到歌、歌太长、显卡被占满、超时）工具报错，她用自己的话婉拒，不刷屏。

## 4. 工具定义（模型看到的样子）

```
name: sing_cover
description: 用你的嗓音翻唱一首歌，作为语音发出去：自动找歌、去掉原唱、换成你的声音，再配上伴奏。
  被要求唱歌、点歌让你唱时用；一轮最多一首。默认唱副歌那一段（约一分钟），要等一两分钟。
  返回歌名、原唱和唱的是哪一段，可以顺口说一句，别把链接写进回复。
parameters:
  song  string 必填  歌名，最好带上原唱歌手，例如"晴天 周杰伦"；也可以是 B 站链接或 BV 号
  part  string 可选  唱哪一段：副歌（默认）/ 开头 / 从某个时间开始，例如 1:20
返回：一句说明文字；语音本身模型看不到，自动附在这条回复后面发出
```

人格文件不改；如果想让她更主动接「唱歌」的梗，我给你建议措辞，你自己加。

## 5. 实现

### 架构

```
dsh 插件 sing_cover ──HTTP──> 网关 /internal/cover/sing ──HTTP──> 翻唱进程（Python，127.0.0.1:5141）
                                 找歌下载、排队、限次、缓存       分离 / 选段 / RVC / 混音
```

- **翻唱进程**（`tools/cover/`）：独立的 Python 环境，网关第一次用到时才启动，空闲 10 分钟自动退出，把显存还给别的程序。启动和加载模型要多花 10–20 秒。
- **网关模块**（`gateway/src/cover/`）：同一时间只唱一首，其他请求排队；排队太久（超过窗口）直接拒绝说「正在唱别的」。按会话每天限次。管理缓存目录。
- **插件**：注册 `sing_cover`，输出用现有的 `media('audio')`，和 `speak` 一样进发件箱。

### 流水线

1. **找歌**（网关里做）：直接调 B 站搜索接口（yt-dlp 的 `bilisearch` 扁平结果没有标题和时长），过滤掉时长不在 1.5–8 分钟的，标题含「翻唱 / cover / 伴奏 / 纯音乐 / DJ / remix / live / 教学 / 钢琴 / 吉他 / 片段」的降权，含「原唱 / 官方 / MV / 完整版」的加分，歌名里的词命中也加分，播放量取对数加分，取最高分。yt-dlp 只下音频，原曲缓存上限 1 GB。
2. **分离**：[audio-separator](https://github.com/nomadkaraoke/python-audio-separator) + BS-Roformer 人声模型（`model_bs_roformer_ep_317_sdr_12.9755.ckpt`，免费），得到人声和伴奏。按歌缓存，留最近 30 首。
3. **选段**：副歌 = 跳过前 20 秒后，人声能量最高的 60 秒窗口，前后对齐到附近的停顿；开头 = 人声第一次出现的位置；指定时间就从那里开始。
4. **换音色**：RVC v2 推理，RMVPE 提取音高，index 率 0.5、protect 0.33（常用默认值，可调）。**自动变调**：原唱人声音高中位数低于 220 Hz（男声）就升 12 个半音，否则不变；配置里可以改成固定值。
5. **混音**：ffmpeg 把新人声和伴奏混在一起（伴奏略压低），首尾各淡入淡出 1.5 秒，响度统一到 -16 LUFS，输出给网关转 silk。

### 推理引擎

用 [Ultimate RVC](https://pypi.org/project/ultimate-rvc/) 0.6.0 的 `VoiceConverter` 做 RVC 推理（RMVPE + ContentVec），它自带 PyTorch 2.7.1 cu128，支持 50 系。分离直接用它依赖的 audio-separator，混音用 pedalboard 混响 + ffmpeg。

环境：用 uv 建 Python 3.12 虚拟环境放在 `tools/cover/.venv`（不进 git），PyTorch 用 cu128 版。分离模型、RMVPE、HuBERT 这些公共权重第一次启动时从 Hugging Face 下载（免费）。

## 6. 限制与保护

- 默认**仅限主人**（加进 `features.ownerOnlyTools`），稳定了再放开。
- 每个群 / 私聊每天最多 10 首（可调）。
- 歌超过 8 分钟不唱；一段最长 90 秒。
- 同时只唱一首；显存不够（加载模型时 OOM）就报错「显卡被占满了」，不重试。
- 计费：本机算力不花钱，不扣 credits，只靠每天限次。
- 版权：角色音色和歌曲都有版权，只在自己群里玩，不对外发布、不商用。

## 7. 配置（看板「配置」页，新分组「翻唱」）

| 配置项 | 默认 | 说明 |
|---|---|---|
| cover.enabled | true | 总开关；关掉后工具不注册 |
| cover.modelDir | assets/cover/voice | 角色包里的音色目录，自动找里面的 .pth / .index |
| cover.lengthSec | 60 | 一段唱多长，30–90 |
| cover.autoTranspose | true | 原唱是男声就自动升 12 个半音 |
| cover.transpose | 0 | 关掉自动变调时用的固定半音数，-24～24 |
| cover.indexRate / cover.protect | 0.5 / 0.33 | RVC 参数 |
| cover.dailyLimit | 10 | 每个群 / 私聊每天最多几首 |
| cover.maxSongMinutes | 8 | 原曲超过这么长不唱 |
| cover.idleMinutes | 10 | 翻唱进程空闲多久退出 |

## 8. 对缓存的影响

新增一个工具会改变发给模型的工具列表，上线后每个会话第一轮要全价付一次（这个群现在约 ¥0.47），之后恢复。会和其他改提示词或工具的改动攒在一起上线。
