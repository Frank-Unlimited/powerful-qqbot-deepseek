# Spec：分层记忆（短期原文 → 长期记忆 → 群友画像）

状态：已实现，待线上测试（2026-10-23），分支 `feat/person-portrait` 上 5 个阶段各一个提交。

> 实现时的调整：
> - 按时间翻原文只能翻当前会话，主人也一样；主人在私聊里能看别的会话的原文，只限顺着长期记忆编号看。
> - 被 @ 或被引用的人，除了画像只放部分分节外，长期记忆也只带群聊来源的。
> - mem0 当前版本只会新增记忆（没有更新、删除事件），所以每条记忆只在记下时挂一个出处。

## 1. 目标

把记忆整理成三层，每一层都能追溯到下面一层：

```
L2 群友画像   每人一份结构化画像，夜间由 L1 融合而成          ── 每节标出处 → L1
L1 长期记忆   她提取出来的事实（mem0），标明说的是谁          ── 每条挂一段原文 → L0
L0 短期记忆   每个群 / 私聊每天的互动原文：群友消息、她的回复、她调用的工具和结果
```

1. **短期记忆**：她和群友每天互动的原文全部留下来，包括群聊消息、她的回复、工具调用和工具结果。
2. **长期记忆**：每条都挂着它在短期记忆里的原文段落（锚点），并标出说的是哪几个群友。
3. **召回**：
   - 默认召回长期记忆和画像。当前发言人和被 @ 的人一定召回，这是保底的那条路。
   - 新增**深度回忆**：从某条长期记忆顺着锚点回到当时的原文，相当于二级检索。也可以直接按时间翻原文，因此**替代 `read_group_history`**，群聊记录本来就是短期记忆。
4. **夜间整理**：把每个群友名下的长期记忆融合成画像。画像在看板上可以审计、修改、锁定、回滚。看板上能一路点下去：画像的某一节 → 用到的长期记忆 → 当时的原文。

不做：群画像（群本身的梗、氛围）；人格文件不动。

## 2. 现状

| 环节 | 现在 | 问题 |
|---|---|---|
| 原文 | `group_messages` 表记下群友消息和她的回复（`user_id='self'`），私聊也记（`group_id='user:<openid>'`），保留 30 天 | 不记工具调用；30 天后就删了；和记忆没有关联 |
| 长期记忆 | mem0，作用域 `user:<openid>` / `group:<openid>` | 只知道存在谁名下，不知道说的是谁，也不知道从哪段对话来的 |
| remember | `about=sender` 或 `about=group` | 记不了"发言人说的关于别人的事" |
| digest | 每 20 条消息把每人的发言交给 mem0 提取，写进 TA 名下，不带她的回复 | 提取不到她答应过的事（约定）；没有出处 |
| 每轮召回 | 本轮正文在"发言人 + 本群"里做语义检索，取前 8 条，低于 minScore 的丢掉 | 话题一跳开，这个人的关键信息就召不回来 |
| `read_group_history` | 按小时读本群消息，最多 24 小时 | 和记忆是两套东西，只能看群友说的话，看不到她当时调了什么工具 |

## 3. 设计

### 3.1 L0 短期记忆（原文）

**不新建表，扩展现有的 `group_messages`**。所有统计、发言榜、digest、新人判断都已经按 `user_id != 'self'` 过滤，新增的行用 `user_id='self'` 天然被排除在外，不影响现有功能。

```sql
ALTER TABLE group_messages ADD COLUMN kind TEXT NOT NULL DEFAULT 'msg';  -- msg 群友消息 | reply 她的回复 | tool 工具调用
ALTER TABLE group_messages ADD COLUMN turn TEXT;   -- 同一轮的消息、回复、工具调用共用一个轮次 id
ALTER TABLE group_messages ADD COLUMN meta TEXT;   -- JSON：工具名、参数、结果摘要、触发原因、发了什么媒体
UPDATE group_messages SET kind = 'reply' WHERE user_id = 'self';  -- 存量回复
CREATE INDEX group_messages_turn ON group_messages(turn);
```

**写入什么**：

| 行 | 什么时候写 | 内容 |
|---|---|---|
| `msg` | 收到消息时（现在就这么写） | 昵称、正文；图片还是 `[图片]` 占位。补记触发她的那条消息所在的 `turn` |
| `tool` | 这一轮跑完后，从 dsh 的事件里按顺序写 | 一次调用一行。`text` 是一句话描述（例如"调用 web_search：深圳天气"），`meta` 里存参数（截到 1000 字）和结果（截到 `toolResultChars`，默认 500 字），失败时记下错误 |
| `reply` | 回复发出去时（现在就这么写） | 回复全文；`meta` 记下附带的媒体（图片、表情、语音、视频）和触发原因（@ / 插话 / 定时任务…） |

**不写进去的**：她看到的消息头（场景头、注入的记忆），这是派生数据，记了只会形成循环；她的思考过程也不记。

**一天**按北京时间切分，以会话为单位：一个群一天就是一页原文。

**保留期**：从 30 天改为 `memory.shortTerm.retentionDays`，默认 180 天。**被长期记忆锚点引用的原文段落永久保留**，清理时跳过。按一个活跃群每天 1000 条、每条约 100 字节估算，一年也就几十 MB。

### 3.1.1 原文分段（episode）——2026-10-23 修订

按天切的问题：一段聊天跨过 0 点会被切成两半；活跃的群一天上千条，一页"原文"根本塞不进上下文。改成按**段**组织原文，"天"只是看板上的浏览入口，不再是切分单位。

**怎么切**（写入时增量切，不用回头重算）：

1. **同一轮不拆**：她的回复、工具调用跟着触发这一轮的消息走，永远和那条消息在同一段。
2. **冷场就切**：和上一段最后一条隔了 `episodeGapMin`（默认 30 分钟）以上，开新的一段。0 点不是分界，聊天跨过 0 点就还是一段。
3. **太长就找停顿切**：一段已经有 `episodeMaxRows`（默认 60）行以后，遇到 3 分钟以上的停顿就切；一直没停顿，到 2 倍长度强制切。这样每段都控制在一屏左右，同时尽量切在自然的停顿上。

**每段的摘要**：段落结束后（冷场超过 gap），网关每 10 分钟把已经结束、还没摘要的段批量交给便宜的模型（`summaryModel`，默认 deepseek-flash），各写一句话摘要，比如"小明和小红聊模型娘设定，她认出了 Gemini 那张"。少于 4 行的段不调模型，直接取第一句话。

**深度回忆按预算取，不按行数**：`deep_recall` 每次返回的原文不超过 `deepRecallChars`（默认 6000 字，大约 3k token），取代原来的"最多 200 行"：

| 用法 | 返回 |
|---|---|
| `memory=记忆编号` | 这条记忆出处所在的段（最多 2 段），出处那几行标 ★。段太长时以 ★ 为中心往两边取，取满预算为止，其余折叠并提示 `episode` + `offset` 继续看 |
| `episode=E12`（可选 `offset`） | 打开一整段；超过预算就分页 |
| `hours` / `date` | 和这段时间有重叠的**完整的段**（不会把跨 0 点的段截断）。放得下就直接给原文，每段前加一行分隔；放不下就给**段目录**：编号、起止时间、几行、谁在聊、摘要，让她挑一段用 `episode` 打开 |
| `who` / `keyword` | 只看相关的行（某人的发言以及她回 TA 的那几轮，或者命中关键词的行和前后两行），按段分组，同样受预算约束 |

这样就是三级检索：段目录（摘要）→ 一段原文 → 段里的某几行，任何一次调用都不会撑爆上下文。

**长期记忆重新映射到段**：锚点仍然记原文的行区间（最精确的证据）。"这条记忆属于哪几段"由锚点推出来：有重点人物的，取 TA 在区间里的发言所在的段；没有的，取区间里所有行所在的段。这样不需要另存映射表，也不会和原文对不上。旧的锚点不用改，上线时把所有老原文按上面的规则补切一遍就自动映射好了。

**保留期也按段**：原文过了保留期，按段整段删除；只要段里有一行被长期记忆引用，**整段**永久保留，深度回忆时上下文是完整的。

**看板**：原文页按段显示，每段有标题行（时间、几行、谁在聊、摘要、从这段记下的长期记忆）。按天选的时候，显示和这一天有重叠的完整的段。

### 3.2 L1 长期记忆：归属人和锚点

在 `store.db` 里加两张关联表，不依赖 mem0 的 metadata 过滤（mem0 只支持等值匹配，数组用不了）：

```sql
-- 这条记忆说的是谁
CREATE TABLE memory_subjects (
  memory_id TEXT NOT NULL, user_id TEXT NOT NULL,
  PRIMARY KEY (memory_id, user_id)
);
-- 这条记忆从哪段原文来（可以有多段：mem0 后来用新对话更新了这条记忆时，追加一个锚点）
CREATE TABLE memory_anchors (
  memory_id TEXT NOT NULL,
  chat      TEXT NOT NULL,     -- group_messages.group_id
  from_id   INTEGER NOT NULL,  -- 原文起止（group_messages.id）
  to_id     INTEGER NOT NULL,
  focus     TEXT,              -- 重点看谁的发言（digest 时是被提取的那个人）
  created   INTEGER NOT NULL
);
```

另外在 mem0 的 metadata 里补两个字段，只用来展示：`reporter`（谁说的）和 `origin`（`group:<openid>` 或 `private`）。

**每种写入途径怎么挂归属人和锚点**：

| 途径 | 存在谁名下 | 归属人 | 锚点 |
|---|---|---|---|
| digest 梳理 | `user:X` | X（由 scope 推出，不写表） | 这一批原文（起止 id），focus=X。mem0 返回 ADD 时新建锚点，UPDATE 时追加锚点，DELETE 时删掉 |
| remember `about=sender` | `user:发言人` | 发言人 | 当前这一轮：触发消息之前最多 10 条（30 分钟内）到这一轮最后一行 |
| remember `about=person, who=某人` **（新增）** | `user:某人` | 某人；reporter=发言人 | 同上 |
| remember `about=group, who=[…]`（who 可选） | `group:群` | who 里的人 | 同上 |
| 看板手动添加 | 选人或选群 | 可多选 | 可以不挂（显示"手动添加，无原文"） |

**digest 顺带改进**：交给 mem0 的除了这个人的发言，还带上这一批里她对 TA 的回复（作为 assistant 消息）。这样能提取出"她答应过 TA 什么"这类约定。

**`who` 怎么解析**：
1. 先看本条消息里 @ 到的人（at 元素带 openid）。
2. 再看被引用消息的作者。
3. 最后按名字或外号匹配本群近 30 天发过言的人，以及 profiles 表里的昵称。

匹配到多个人就报错并列出候选人，匹配不到也报错。私聊里 `who` 只能是对方自己，主人例外。

**存量记忆**：
- `user:` 名下的不用补归属人。
- 有 `group` 字段的 digest 记忆，按"那个群、创建时间往前 2 小时内这个人的发言"补一个近似锚点，标成"推测"。原文已经被清理掉的，就显示"无原文"。
- `group:` 名下的记忆，第一次夜间整理时让模型补标归属人，只标人，不改内容。

### 3.3 L2 群友画像

```sql
CREATE TABLE portraits (
  user_id TEXT PRIMARY KEY, data TEXT NOT NULL, version INTEGER NOT NULL,
  updated INTEGER NOT NULL, by TEXT NOT NULL,   -- night | dashboard | rollback
  watermark INTEGER NOT NULL                    -- 整理时看到的最新记忆时间
);
CREATE TABLE portrait_history (
  user_id TEXT NOT NULL, version INTEGER NOT NULL, data TEXT NOT NULL,
  time INTEGER NOT NULL, by TEXT NOT NULL, note TEXT,
  PRIMARY KEY (user_id, version)
);
```

`data` 由固定的几节组成，每节是一段短文本，附上出处（L1 的短 id）和是否锁定：

```jsonc
{
  "sections": {
    "identity":  { "text": "小明，她叫他"明哥"，是她的主人……", "sources": ["a1b2c3d4"], "locked": false },
    "persona":   { … },   // 性格、说话风格
    "likes":     { … },   // 喜好与雷点
    "recent":    { … },   // 近况与计划（最容易过时）
    "bond":      { … },   // 和她的关系、约定、称呼
    "relations": { … },   // 和其他群友的关系
    "note":      { "text": "", "sources": [], "locked": true }   // 主人手写备注，整理永远不碰
  },
  "summary": "一句话版本（不超过 60 字）"
}
```

- 全文不超过 600 字。
- 锁定的分节，夜间整理不改。没锁定但手动改过的分节，作为现有版本交给模型，规则是"除非有更新的记忆明确推翻，否则保留"。
- 每次变化（夜间整理、看板修改、回滚）都写进 `portrait_history`，可以对比差异、回滚。

### 3.4 召回

#### 默认召回（每轮自动放进消息头）

**路 A：按人保底召回（新增）**

这一轮"在场的人"有：
- 发言人；
- 本条消息里 @ 到的人；
- 被引用消息的作者。

除发言人外最多再带 `mentionLimit` 个（默认 2）。对每个人：
- 放进 TA 的画像；
- 在 TA 名下（`user:TA` 加上挂到 TA 的群记忆）按本轮正文检索，取前 `personLimit` 条（默认 3），**不受 minScore 过滤**。

**路 B：语义召回（现有）**：在"发言人 + 本群"里做语义检索，结果去掉路 A 已经有的。

每条长期记忆后面带上原文日期，提示她这条有原文可以深挖：

```
[关于 明哥（发言人）] 小明，她叫他"明哥"，是她的主人；说话直，爱玩梗；最近在折腾 QQ 机器人……
  #a1b2c3d4 明哥说下周要出差（10-21 本群）
[关于 小明（被@）] 一句话版本……
[相关记忆]
  #e5f6a7b8 （本群）群里约好周六一起打本（10-19 本群）
```

**省 token**：
- 画像全文在同一个会话里只放一次。之后只放 summary，直到画像版本变了，或者超过 `reinjectHours`（默认 6 小时）。dsh 会话历史是只追加的，前面放过的全文还在上下文里。
- 被 @ 或被引用的人只放 summary 和 likes、relations 两节，不放 recent、bond，避免把 TA 的私事带进别人的对话。

#### 主动回忆：`recall`（L1 和 L2）

- 参数：`query`，可选 `who`（专门回忆某个群友，结果带上 TA 的画像）。
- 返回每条记忆的短 id、内容，以及有没有原文（日期、哪个会话）。

#### 深度回忆：`deep_recall`（新工具，L0；**替代 `read_group_history`**）

两种用法，二选一：

| 用法 | 参数 | 返回 |
|---|---|---|
| 顺着记忆往下挖 | `memory`：长期记忆的短 id | 这条记忆所有锚点对应的原文，每段前后各多给 3 行上下文 |
| 直接翻原文 | `hours`（往前几小时，默认 3，最多 72），或 `date`（`10-21`、`昨天`）；可选 `who`（只看某人和她跟 TA 的来回）、`keyword` | 那段时间本会话的原文 |

- **返回格式**：一行一条，`时间 昵称：内容`。她自己的回复显示为 `你：…`，工具调用显示为 `你 → 调用 web_search（深圳天气）：结果摘要…`。
- **长度控制**：~~每次最多 `deepRecallRows` 行~~ 已改为按字数预算 `deepRecallChars`、按段返回，见第 3.1.1 节。
- **权限**：只能看**当前会话**的原文。在群里看本群；私聊里看和对方的私聊；主人在私聊里可以看任何会话。长期记忆的锚点如果指向别的会话（比如一条在私聊里记下的记忆，在群里被召回），只返回"这条的原文在别处，不能在这里看"，不泄露内容。
- **迁移**：
  - `read_group_history` 下线，工具总数不变（还是 15 个）。
  - 群聊总结命令里写死的 `read_group_history` 改成 `deep_recall`。
  - 日记任务的默认提示改成 `deep_recall`；私有角色包 `config.yaml` 里第 144 行的日记提示也一起改。这是配置，不是人格文件。
  - 人格文件里没有提到 `read_group_history`，不用改。

### 3.5 夜间整理

网关内部的后台任务，不在聊天里发消息，也不走 dsh：

- **时间**：`memory.night.time`，默认 `04:00`（北京时间）。错过了当天补跑，每天最多一次。看板上可以对单个人「立即整理」。
- **选人**：满足下面任一条件的人，最多 `maxPeople` 人（默认 30）：
  - 有画像，且名下有比 watermark 更新的记忆；
  - 没有画像，且名下记忆数 ≥ `minMemories`（默认 3）。
- **单人流程**：
  1. 收集 TA 名下**群聊来源**的长期记忆（私聊来源的不进画像，判定规则见第 6 节第 2 条）。超过 150 条时，取最新的和被召回最多的各一半。每条附上短 id、来源、时间、召回次数、是不是转述。
  2. 带上当前画像和锁定情况，调一次 DeepSeek（JSON 输出），得到新的 sections 和 summary，每节写明 sources。
  3. 网关校验：分节齐全、长度不超、sources 里的 id 确实存在、锁定分节原样保留。校验不过就跳过，旧画像不动。
  4. 写入新版本和 history，推进 watermark。
- **提示词要点**：
  - 新记忆推翻旧记忆；
  - 转述的内容写成"据 XX 说"；
  - 不写联系方式、住址、真实姓名、健康状况，也不写对方说过"别告诉别人"的事；
  - 没有出处的不写。
- **只读原文吗？** 夜间整理只读 L1，不直接读 L0。原文已经在白天被 digest 提取过了，再读一遍费 token，也容易把闲聊写进画像。
- **原始记忆不删不改**：画像是派生出来的。
- **费用**：后台费用，不扣任何人的额度。活动记录里加一条"夜间整理：N 人，更新 M 份画像"。

### 3.6 看板

「记忆」页分成三个子页，对应三层，彼此可以点击跳转：

| 子页 | 内容 |
|---|---|
| **短期记忆** | 选会话加日期，按时间线展示当天原文：群友消息、她的回复（区分颜色）、工具调用（折叠成小标签，点开看参数和结果）。被长期记忆引用的段落旁边标出记忆编号，点了跳到那条记忆。可以按人、按关键词筛选 |
| **长期记忆**（现有页面增强） | 每条显示归属人（可改）、reporter、召回统计（现有）。「原文」按钮跳到短期记忆对应的段落并高亮，近似锚点标"推测"。可以按人筛选 |
| **群友画像** | 列表：昵称、名下记忆数、画像版本、更新时间、待整理数。详情：各分节可编辑、可锁定，出处标签点了跳长期记忆；历史版本可以对比和回滚；「立即整理」按钮 |

## 6. 审核结论（2026-10-23）

1. 转述的记忆存在被说的人名下，标 reporter，画像里写"据 XX 说"。
2. **私聊内容不进画像**。夜间整理只用群聊来源的长期记忆，下面这些都排除：digest 没有 group 字段的；`origin=private` 的；锚点全部在私聊里的。存量里 `tool` 来源、判断不出来源的记忆，先按活动记录（创建时刻那一轮的会话）推断；还是推断不出来的，保守起见也排除。手动添加和旧版迁移的照常使用。私聊里的记忆照常参与召回（路 A、路 B 都算），只是不进画像。
3. 原文保留 180 天，被引用的段落永久保留。
4. 夜间整理 04:00。
5. 这一版不去重、不合并长期记忆。
